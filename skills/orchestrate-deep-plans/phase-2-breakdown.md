# Phase 2 — Break the milestone into stories

1. **Contract:** `podium set milestone:<id> quality.contract=<[{"cmd"}] with one entry: the gates.sh call from deep-plan's Shared rules, with . as the directory, since merge runs cmd in the story's worktree>`. `merge` runs that contract, and each brief names it. Then `podium approve`, and `podium approve <digest>...` for the `PENDING` commands you just wrote, and only those; any other `PENDING` line → show it to the user, and approve it only on their yes.
2. **Break it down:** `podium breakdown <spec>/tasks.md --milestone <id> --dry-run`, beside another milestone with `--prefix <its letter>` (`W` for `W1`, `W2`, …: SKILL.md, Running two milestones at once). It turns each `## Phase <n>: User Story <k>` section of speckit's `tasks.md` into story `S<k>` (`title`, a one-line `summary` from its `**Goal**:`, `files` from the paths its task lines name, `deps` from the `## Dependencies` section, `overlapAfter`, `critical`, `model`) and its brief, `podium/stories/<milestone>/<id>.md`. Act on its lines:
   - `STORY <id> <repo> deps=<ids> files=<n> missing=<fields>`, one per story. Check each `deps` against the rule: a story depends on another only when it needs that story's code — an interface, a migration, a module. A wrong or missing one → fix the Dependencies section, one sentence per story (`US3 depends on US1 and US2`, `US2 needs nothing from US1`).
   - `MISSING <id> critical` → the story runs on `sonnet` until its section gets a `**Critical**: yes` or `no` line: yes for correctness-critical stories (money, dates and time zones, concurrency, auth, migrations, core algorithms). A section without the line whose title, goal or tasks name one of those is already `opus`: check those the same way.
   - `MISSING <id> context` → add a `**Context**:` line to its section (Briefs, below).
   - `MISSING <id> <field>` for `story` (no `**Goal**:`), `deps` (the Dependencies section doesn't name it), `files` or `tasks`; `MISSING <id> dep <id>` (it names a user story with no section); `MISSING <id> ref <ref>` (a reference that matches no heading) → fix `tasks.md` or the planning file.
   - `OVERLAP <a> <b> <file>`: two stories with no dependency path share a file, so `<b>` waits for `<a>` and they land in different waves.
   - `WAVES <ids> | <ids> …`; `CYCLE <ids>` → those stories' dependencies loop and nothing was written: fix the Dependencies section.

   Rerun until the lines are clean, then run it without `--dry-run`. A rerun updates each story in place and rewrites its brief; `KEPT <id> started` → that story was dispatched already, so it and its brief stay as they are. `podium ls stories --fields model,deps,overlapAfter` shows what it wrote.
3. **Briefs:** the story's agent starts from `podium brief <milestone>/<id>`, which prints the brief and each planning section it references, and reads nothing else of the plan. The brief carries the section's Goal, Acceptance (its task lines), Files in scope, Context, Contract and Done when. Context is the section's `**Context**:` items, its user story's heading in the `spec.md` beside `tasks.md`, and its own section of `tasks.md`. So each section's `**Context**:` line names the other sections the story builds on, comma-separated, in backticks as `<file>#<heading text>` with the file's path from `.deep-plan/`: the `architecture.md` interfaces and seams it builds on. `brief` also prints every section, of any planning file, whose heading matches a phrase in backticks or quotes, and with two milestones building, the main checkout's `.deep-plan/architecture*.md` counts for both: backtick a name only when its section belongs in the brief.
4. **Publish:** `podium set milestone:<id> phase=build --event phase phase=build`.
5. **Hand over:** start the watcher (SKILL.md, Podium) and tell the user in one message: the Podium link, N stories in M waves, and that they can assign stories one by one or press Build all. End the turn; the watcher wakes you.

Done when every user story in `tasks.md` has a brief and a `podium.json` entry, `podium breakdown` prints no `MISSING` or `CYCLE` line, `podium brief` prints no `MISSING` line for any story, the graph is acyclic with no shared file inside one wave, and the user has the link.
